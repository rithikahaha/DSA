# 15. 3Sum
LeetCode: https://leetcode.com/problems/3sum/ · Medium · Pattern: Sort + two pointers

## Problem
Given a list `nums`, find **all groups of three numbers that add up to 0**. Each group must use three different positions, and the answer must **not contain the same group twice**.

```
Input:  nums = [-1, 0, 1, 2, -1, -4]
Output: [[-1, -1, 2], [-1, 0, 1]]
```

## Words you need first
| Word | Plain-English meaning |
|---|---|
| **triplet** | A group of three numbers. |
| **sorting** | Putting numbers in order, smallest to biggest. `[-1,0,1,2,-1,-4]` → `[-4,-1,-1,0,1,2]`. |
| **two pointers** | Two markers, `l` and `r`, moving toward each other through a sorted list. |

## How to come up with it (the thinking)
**Step 1: the obvious idea.** Try every group of three: three loops inside each other. For 1,000 numbers that's about a billion checks. Too slow.

**Step 2: shrink the problem.** Pick the first number `a`. Now we only need **two more numbers that add up to `-a`**. That's like Two Sum, but on a sorted list.

**Step 3: sorted lists let us steer.** Put `l` just after `a` and `r` at the far end. Look at `a + nums[l] + nums[r]`:
- **Too big (> 0)?** Move `r` left to get a smaller number.
- **Too small (< 0)?** Move `l` right to get a bigger number.
- **Exactly 0?** Save the triplet, then move on.

**Step 4: avoiding duplicates.** Sorting puts equal numbers side by side. If `a` is the same as the previous `a`, skip it (it would produce the same triplets again). After saving a triplet, move `l` past any repeated values too.

## Solution
```python
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        res = []
        nums.sort()

        for i, a in enumerate(nums):
            if i > 0 and a == nums[i - 1]:
                continue

            l, r = i + 1, len(nums) - 1
            while l < r:
                threeSum = a + nums[l] + nums[r]
                if threeSum > 0:
                    r -= 1
                elif threeSum < 0:
                    l += 1
                else:
                    res.append([a, nums[l], nums[r]])
                    l += 1
                    while nums[l] == nums[l - 1] and l < r:
                        l += 1
        return res
```

## Line by line
| Line | What it does |
|---|---|
| `res = []` | The list of triplets found. |
| `nums.sort()` | Sort the numbers. This is what makes the steering possible. |
| `for i, a in enumerate(nums):` | Pick each number as the first member `a` (`i` is its position). |
| `if i > 0 and a == nums[i-1]: continue` | Same as the previous first number → skip it, to avoid duplicate triplets. |
| `l, r = i + 1, len(nums) - 1` | `l` starts right after `a`; `r` starts at the very end. |
| `while l < r:` | Keep going until the pointers meet. |
| `threeSum = a + nums[l] + nums[r]` | Add the three numbers. |
| `if threeSum > 0: r -= 1` | Too big → use a smaller right number. |
| `elif threeSum < 0: l += 1` | Too small → use a bigger left number. |
| `else:` | The sum is exactly 0. |
| `res.append([a, nums[l], nums[r]])` | Save the triplet. |
| `l += 1` | Move `l` on. |
| `while nums[l] == nums[l-1] and l < r: l += 1` | Skip over repeated left values so the same triplet isn't saved twice. |

## Watch it run
`nums = [-1, 0, 1, 2, -1, -4]` → sorted: `[-4, -1, -1, 0, 1, 2]` (positions 0 to 5)

| `i` | `a` | `l`, `r` | Numbers | Sum | What happens |
|---|---|---|---|---|---|
| 0 | -4 | 1, 5 | -1, 2 | -3 | too small → `l` moves. Every sum stays negative until `l` meets `r`. **No triplet.** |
| 1 | -1 | 2, 5 | -1, 2 | 0 | **Save `[-1,-1,2]`**, `l = 3` (0 is different from -1, so no skipping) |
| 1 | -1 | 3, 5 | 0, 2 | 1 | too big → `r = 4` |
| 1 | -1 | 3, 4 | 0, 1 | 0 | **Save `[-1,0,1]`**, `l = 4`, pointers meet |
| 2 | -1 | | | | same as previous `a` → **skip** |
| 3 | 0 | 4, 5 | 1, 2 | 3 | too big → `r = 4`, pointers meet |
| 4, 5 | 1, 2 | | | | not enough numbers to the right |

Result: `[[-1,-1,2], [-1,0,1]]` ✅

## How fast is it?
- **Time: O(n²).** For each of n choices of `a`, the two pointers sweep the list once (about n steps). Sorting adds O(n log n), which is smaller.
- **Space: O(1) extra.** Not counting the answer list.
