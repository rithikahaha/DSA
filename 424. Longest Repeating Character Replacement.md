# 424. Longest Repeating Character Replacement
LeetCode: https://leetcode.com/problems/longest-repeating-character-replacement/ · Medium · Pattern: Sliding window

## Problem
Given an uppercase string `s` and an integer `k`, you may replace at most `k` characters with any other uppercase letter. Return the length of the longest substring you can make out of a single repeated letter.

**Example 1**
```
Input: s = "XYYX", k = 2
Output: 4      (change both X's to Y, or both Y's to X)
```

**Example 2**
```
Input: s = "AAABABB", k = 1
Output: 5      ("AAABA" → change the B to A)
```

## Solution
```python
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        count = {}
        res = 0

        l = 0
        maxf = 0
        for r in range(len(s)):
            count[s[r]] = 1 + count.get(s[r], 0)
            maxf = max(maxf, count[s[r]])

            while (r - l + 1) - maxf > k:
                count[s[l]] -= 1
                l += 1

            res = max(res, r - l + 1)
        return res
```

Using `s = "AAABABB"`, `k = 1`:

1. The window `s[l..r]` can become one repeated letter if `window length - count of its most frequent letter <= k`. Keep the majority letter and replace the rest.
2. `count` tracks letters in the window and `maxf` is the highest count seen.
3. Grow `r` over `A A A B A`: counts `A:4, B:1`, `maxf = 4`. Replacements needed = `5 - 4 = 1 <= 1` → valid, `res = 5`.
4. Next `r` adds `B` → window `AAABAB` (length 6): counts `A:4, B:2`, replacements = `6 - 4 = 2 > 1` → invalid.
5. Shrink: remove `s[l]`, `l += 1`. Window is now length 5 again → still valid, `res` stays 5.
6. Adding the last `B` behaves the same way. Result → `5`.

`maxf` is never lowered when the window shrinks. That's safe: a new window can only beat the current best if `maxf` actually increases, so the stale value never produces a wrong answer. O(n) time, O(1) space (26 letters).
