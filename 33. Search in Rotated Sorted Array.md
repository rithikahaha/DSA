# 33. Search in Rotated Sorted Array
LeetCode: https://leetcode.com/problems/search-in-rotated-sorted-array/ · Medium · Pattern: Binary search

## Problem
A sorted array of distinct values was rotated (e.g. `[0,1,2,4,5,6,7]` → `[4,5,6,7,0,1,2]`). Given a `target`, return its index, or `-1` if it isn't present. It must run in O(log n).

**Example 1**
```
Input: nums = [3,4,5,6,1,2], target = 1
Output: 4
```

**Example 2**
```
Input: nums = [3,5,6,0,1,2], target = 4
Output: -1
```

## Solution
```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        l, r = 0, len(nums) - 1
        while l <= r:
            mid = (l + r) // 2
            if target == nums[mid]:
                return mid

            if nums[l] <= nums[mid]:
                if target > nums[mid] or target < nums[l]:
                    l = mid + 1
                else:
                    r = mid - 1
            else:
                if target < nums[mid] or target > nums[r]:
                    r = mid - 1
                else:
                    l = mid + 1
        return -1
```

Using `nums = [3,4,5,6,1,2]`, `target = 1`:

1. After splitting at `mid`, at least one half is always sorted. Work out which one, then check whether the target falls inside its range.
2. `l = 0`, `r = 5`, `mid = 2`, `nums[2] = 5` (not the target).
3. `nums[l] <= nums[mid]` (3 ≤ 5) → the **left half `3,4,5` is sorted**. The target is not inside `[3, 5]` (it's `< nums[l]`), so it must be on the right → `l = mid + 1 = 3`.
4. `mid = 4`, `nums[4] = 1` equals the target → return `4`.
5. In the other branch (`nums[l] > nums[mid]`), the **right half is sorted**. If the target is outside `[nums[mid], nums[r]]` it must be on the left (`r = mid - 1`), otherwise on the right (`l = mid + 1`).

It's ordinary binary search with one extra question ("which half is sorted?"), so it stays O(log n) time and O(1) space.
