# 33. Search in Rotated Sorted Array
LeetCode: https://leetcode.com/problems/search-in-rotated-sorted-array/ · Medium · Pattern: Binary search

## Problem
A sorted list of different numbers was **rotated** (the tail moved to the front). Given a `target`, return its **index**, or `-1` if it's not there. It must run in O(log n).

```
Input: nums = [3, 4, 5, 6, 1, 2],  target = 1     Output: 4
Input: nums = [3, 5, 6, 0, 1, 2],  target = 4     Output: -1
```

## Words you need first
| Word | Plain-English meaning |
|---|---|
| **rotated** | Sorted list with its tail moved to the front: `[1,2,3,4,5,6]` → `[3,4,5,6,1,2]`. |
| **`l`, `r`, `mid`** | Left end, right end and middle of the part still being searched. |
| **sorted half** | After cutting at `mid`, at least **one** of the two halves is perfectly in order. |

## How to come up with it (the thinking)
**Step 1: plain binary search doesn't work.** In ordinary binary search we compare the middle with the target to decide left or right. In a rotated list the order is broken, so that comparison alone can mislead us.

**Step 2: the key fact.** Cut the list at `mid`. **One half is always sorted.** (Only one half can contain the "drop" where big numbers turn into small ones.)

**Step 3: find out which half is sorted.** If `nums[l] <= nums[mid]`, the left half is sorted. Otherwise the right half is sorted.

**Step 4: ask "is the target inside the sorted half?"** In a sorted half, checking whether a number belongs there is easy: it must fit between the two ends.
- Target is inside the sorted half → search that half.
- Otherwise → it can only be in the other half.

## Solution
```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        l, r = 0, len(nums) - 1
        while l <= r:
            mid = (l + r) // 2
            if target == nums[mid]:
                return mid

            if nums[l] <= nums[mid]:
                if target > nums[mid] or target < nums[l]:
                    l = mid + 1
                else:
                    r = mid - 1
            else:
                if target < nums[mid] or target > nums[r]:
                    r = mid - 1
                else:
                    l = mid + 1
        return -1
```

## Line by line
| Line | What it does |
|---|---|
| `l, r = 0, len(nums) - 1` | Start by searching the whole list. |
| `mid = (l + r) // 2` | Middle position. |
| `if target == nums[mid]: return mid` | Found it. |
| `if nums[l] <= nums[mid]:` | **Left half is sorted.** |
| `if target > nums[mid] or target < nums[l]:` | Target is bigger than the middle, or smaller than the left end → it's **not** in the left half. |
| `l = mid + 1` | So search the right half. |
| `else: r = mid - 1` | Otherwise it's inside the left half → search there. |
| `else:` (right half is sorted) | The mirror image of the above. |
| `if target < nums[mid] or target > nums[r]:` | Target is smaller than the middle, or bigger than the right end → **not** in the right half. |
| `r = mid - 1` | So search the left half. |
| `else: l = mid + 1` | Otherwise it's in the right half. |
| `return -1` | The search area is empty → not found. |

## Watch it run
`nums = [3, 4, 5, 6, 1, 2]` (positions 0 to 5), `target = 1`

| Round | `l` | `r` | `mid` | `nums[mid]` | Sorted half | Is target 1 in it? | Decision |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 5 | Left (3 ≤ 5): `3,4,5` | No (1 < 3, below the left end) | search right → `l = 3` |
| 2 | 3 | 5 | 4 | 1 | | `nums[mid] == 1` | **return 4** |

Answer: **4** ✅

## How fast is it?
- **Time: O(log n).** Half of the list is discarded each round.
- **Space: O(1).**
