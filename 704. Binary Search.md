# 704. Binary Search
LeetCode: https://leetcode.com/problems/binary-search/ · Easy · Pattern: Binary search

## Problem
`nums` is a list of numbers **already sorted** from smallest to biggest. Return the **index (position)** of `target`, or `-1` if it isn't in the list. It must be fast: O(log n).

```
Input: nums = [-1, 0, 2, 4, 6, 8],  target = 4     Output: 3
Input: nums = [-1, 0, 2, 4, 6, 8],  target = 3     Output: -1
```

## Words you need first
| Word | Plain-English meaning |
|---|---|
| **sorted** | In order, smallest to largest. This is what makes the trick possible. |
| **index** | A number's position in the list, starting at 0. |
| **`l`, `r`, `m`** | Left end, right end, and middle of the part of the list we're still searching. |
| **`//`** | Division that drops the decimal part: `5 // 2` is `2`. |

## How to come up with it (the thinking)
**Step 1: the obvious idea.** Check every number from the start until you find the target. For a million numbers, that could be a million checks.

**Step 2: think of guessing a number.** Someone picks a number from 1 to 100. You guess 50 and they say "higher". Now you know it's in 51–100, and you've thrown away **half** of the possibilities with one guess. Guess the middle of what's left, again and again.

**Step 3: same idea here.** Because the list is sorted, look at the **middle** number:
- Middle is **bigger** than the target → the target must be in the left half. Ignore everything from the middle onward.
- Middle is **smaller** than the target → the target must be in the right half. Ignore everything up to the middle.
- Middle **equals** the target → found it!

**Step 4: how many steps?** Halving a million items takes only about 20 steps.

## Solution
```python
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        l, r = 0, len(nums) - 1
        while l <= r:
            m = l + ((r - l) // 2)
            if nums[m] > target:
                r = m - 1
            elif nums[m] < target:
                l = m + 1
            else:
                return m
        return -1
```

## Line by line
| Line | What it does |
|---|---|
| `l, r = 0, len(nums) - 1` | At first, we search the whole list: from position 0 to the last position. |
| `while l <= r:` | Keep going while there's still something left to search. |
| `m = l + ((r - l) // 2)` | The middle position between `l` and `r`. |
| `if nums[m] > target: r = m - 1` | Middle is too big → the target is to the left. Move the right end to just before the middle. |
| `elif nums[m] < target: l = m + 1` | Middle is too small → the target is to the right. Move the left end to just after the middle. |
| `else: return m` | Middle equals the target → return its position. |
| `return -1` | The search area became empty (`l > r`), so the target isn't there. |

## Watch it run
`nums = [-1, 0, 2, 4, 6, 8]` (positions 0 to 5), `target = 4`

| Round | `l` | `r` | `m` | `nums[m]` | Compare with 4 | What happens |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 2 | 2 | smaller | target is on the right → `l = 3` |
| 2 | 3 | 5 | 4 | 6 | bigger | target is on the left → `r = 3` |
| 3 | 3 | 3 | 3 | 4 | **equal** | return `3` |

Answer: **3** ✅

## How fast is it?
- **Time: O(log n).** Each round throws away half of the remaining numbers.
- **Space: O(1).** Just three variables.
