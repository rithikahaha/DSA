# 213. House Robber II
LeetCode: https://leetcode.com/problems/house-robber-ii/ · Medium · Pattern: Dynamic programming (run it twice)

## Problem
Same as House Robber, except the houses are arranged in a **circle**, so the first and last houses are neighbours. You can't rob two adjacent houses. Return the maximum you can rob.

**Example 1**
```
Input: nums = [3,4,3]
Output: 4      (rob the middle house; 3 + 3 isn't allowed since they're adjacent)
```

**Example 2**
```
Input: nums = [2,9,8,3,6]
Output: 15     (9 + 6)
```

## Solution
```python
class Solution:
    def rob(self, nums: List[int]) -> int:
        return max(nums[0], self.helper(nums[1:]), self.helper(nums[:-1]))

    def helper(self, nums):
        rob1, rob2 = 0, 0

        for n in nums:
            newRob = max(rob1 + n, rob2)
            rob1 = rob2
            rob2 = newRob
        return rob2
```

Using `nums = [2,9,8,3,6]`:

1. In a circle, house 0 and the last house touch, so you can never take both.
2. That gives two separate straight-line problems: **skip the first house** (`nums[1:]`) or **skip the last house** (`nums[:-1]`). The best plan lies in one of the two.
3. `helper` is exactly House Robber (problem 198) on a plain line of houses.
4. Skipping the first house: `helper([9,8,3,6])` = 15 (9 + 6). Skipping the last house: `helper([2,9,8,3])` = 12 (9 + 3). Take the larger → `15`.
5. `nums[0]` is included in the `max` to handle a single house: with one house, both slices are empty (result 0), but robbing it is allowed.

Two linear passes: O(n) time. Slicing copies the list, so space is O(n) here; index bounds could avoid that.
