# 1. Two Sum
LeetCode: https://leetcode.com/problems/two-sum/ · Easy · Pattern: Hash map

## Problem
You get a list of numbers `nums` and a number `target`. Find the **two numbers in the list that add up to `target`** and return their positions (indices). There is exactly one answer, and you can't use the same number twice.

```
Input:  nums = [3, 4, 5, 6],  target = 7
Output: [0, 1]        because nums[0] + nums[1] = 3 + 4 = 7
```

## Words you need first
| Word | Plain-English meaning |
|---|---|
| **list / array** | A row of numbered boxes. The box number is called the **index**, and it starts at **0**. In `[3,4,5,6]`, box 0 holds 3, box 1 holds 4. |
| **dictionary (hash map)** | Like a phone book. You look someone up **by name** and instantly get their number, without reading every page. Here the "name" is a number from the list and the "phone number" is its box number. |
| **`enumerate`** | A Python helper that hands you the box number **and** what's inside it at the same time. |

## How to come up with it (the thinking)
**Step 1: the obvious idea.** Take the first number, 3. Ask: "what partner do I need?" `7 - 3 = 4`. Now look through the *whole* list for a 4. Then take the next number, and look through the whole list again... This works, but with 1,000 numbers you'd do about 1,000 × 1,000 = **1,000,000** checks. Very slow.

**Step 2: what's wasteful?** Every time, we *search the whole list* for the partner. We keep re-reading the same numbers.

**Step 3: the trick.** Walk through the list **once**, and write down every number you've already passed (and where it was) in a phone book. When you arrive at a new number, you don't search anything. You just ask the phone book: *"Have I already passed the partner I need?"* The phone book answers instantly.

**Step 4: why it finds the answer.** If two numbers A and B make the target, one of them comes first in the list. When you reach the second one, the first one is already in your phone book, so you spot it.

## Solution
```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        prevMap = {}  # value -> index

        for i, n in enumerate(nums):
            diff = target - n
            if diff in prevMap:
                return [prevMap[diff], i]
            prevMap[n] = i
        return
```

## Line by line
| Line | What it does |
|---|---|
| `prevMap = {}` | Make an empty phone book. Later it will hold things like `{3: 0}`, meaning "number 3 lives in box 0". |
| `for i, n in enumerate(nums):` | Go through the list one number at a time. `i` = the box number, `n` = the number inside. |
| `diff = target - n` | Work out the partner needed. If `n` is 3 and the target is 7, then `diff` is 4 (because 3 + 4 = 7). |
| `if diff in prevMap:` | Ask the phone book: "Did I already pass a number equal to `diff`?" |
| `return [prevMap[diff], i]` | Yes! Return where the partner lives (`prevMap[diff]`) and where we are now (`i`). Done. |
| `prevMap[n] = i` | No partner yet, so write the current number into the phone book for later numbers to find. |

Note that we check **first** and store **after**. That way a number can never match with itself.

## Watch it run
`nums = [3, 4, 5, 6]`, `target = 7`

| Step | `i` | `n` | `diff = 7 - n` | `prevMap` before | Is `diff` in it? | What happens |
|---|---|---|---|---|---|---|
| 1 | 0 | 3 | 4 | `{}` | No | Store 3 → `prevMap = {3: 0}` |
| 2 | 1 | 4 | 3 | `{3: 0}` | **Yes**, at index 0 | Return `[0, 1]` |

The code stops at step 2, so it never looks at 5 or 6.

## How fast is it?
- **Time: O(n).** It walks the list once. Each phone-book lookup is instant. For 1,000 numbers, that's about 1,000 steps instead of 1,000,000.
- **Space: O(n).** The price we pay is the phone book, which can hold up to n numbers.
