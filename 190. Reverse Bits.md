# 190. Reverse Bits
LeetCode: https://leetcode.com/problems/reverse-bits/ · Easy · Pattern: Bit manipulation

## Problem
Given a **32-bit** number `n`, reverse the order of its bits and return the new number.

```
Input:  00000000000000000000000000010101   (21)
Output: 10101000000000000000000000000000   (2818572288)
```

## Words you need first
| Word | Plain-English meaning |
|---|---|
| **bit** | One binary digit (0 or 1). A 32-bit number has 32 of them, in **positions 0 to 31, counted from the right**. |
| **`n >> i`** (right shift) | Slide all bits `i` places to the right. The bit that was at position `i` lands at position 0. |
| **`& 1`** | "Keep only the last bit": everything else is turned into 0. |
| **`bit << k`** (left shift) | Slide a bit `k` places left, to position `k`. |
| **OR (the `\|` symbol)** | Combine two numbers: a bit is 1 if it's 1 in **either** one. Used to "write" a bit into the result without disturbing other bits. |

## How to come up with it (the thinking)
**Step 1: what does reversing mean?** The bit at position `i` moves to position `31 − i`. The rightmost bit (position 0) becomes the leftmost (position 31), and so on.

**Step 2: do it one bit at a time.** For each position `i` from 0 to 31:
1. **Read** the bit at position `i`: `(n >> i) & 1`. The shift brings it to the end; `& 1` isolates it.
2. **Write** it at position `31 − i`: `bit << (31 − i)`.
3. **Combine** it into the result with `|`.

## Solution
```python
class Solution:
    def reverseBits(self, n: int) -> int:
        res = 0

        for i in range(32):
            bit = (n >> i) & 1
            res = res | (bit << (31 - i))
        return res
```

## Line by line
| Line | What it does |
|---|---|
| `res = 0` | The reversed number, starting as all zeros. |
| `for i in range(32):` | Handle each of the 32 positions, 0 through 31. |
| `bit = (n >> i) & 1` | Read the bit at position `i` (it's 0 or 1). |
| `bit << (31 - i)` | Move that bit to the mirrored position `31 − i`. |
| `res = res \| ...` | Write it into `res`, keeping all the bits already placed. |
| `return res` | The reversed number. |

## Watch it run
To keep the table small, imagine **8 bits** instead of 32 (the mirror position becomes `7 − i`). `n = 00010101`.

Bits of `n` by position (right to left): pos0 = 1, pos1 = 0, pos2 = 1, pos3 = 0, pos4 = 1, pos5 = 0, pos6 = 0, pos7 = 0.

| `i` | `bit` at position `i` | Goes to position `7 − i` | `res` after |
|---|---|---|---|
| 0 | 1 | 7 | `10000000` |
| 1 | 0 | 6 | `10000000` |
| 2 | 1 | 5 | `10100000` |
| 3 | 0 | 4 | `10100000` |
| 4 | 1 | 3 | `10101000` |
| 5 | 0 | 2 | `10101000` |
| 6 | 0 | 1 | `10101000` |
| 7 | 0 | 0 | `10101000` |

`00010101` reversed is `10101000` ✅. The real problem does exactly this with `31 − i` and 32 positions.

## How fast is it?
- **Time: O(1).** Always exactly 32 loops.
- **Space: O(1).**
