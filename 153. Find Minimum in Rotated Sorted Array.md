# 153. Find Minimum in Rotated Sorted Array
LeetCode: https://leetcode.com/problems/find-minimum-in-rotated-sorted-array/ · Medium · Pattern: Binary search

## Problem
A sorted list of different numbers was **rotated**: some numbers were moved from the end to the front. Find the **smallest number** in O(log n).

```
Original: [1, 2, 3, 4, 5, 6]   →   Rotated: [3, 4, 5, 6, 1, 2]
Input:  nums = [3, 4, 5, 6, 1, 2]     Output: 1
Input:  nums = [4, 5, 0, 1, 2, 3]     Output: 0
```

## Words you need first
| Word | Plain-English meaning |
|---|---|
| **rotated** | Take the tail of a sorted list and move it to the front. |
| **two runs** | A rotated list is two sorted stretches back to back: a **big-number run** (`3,4,5,6`) followed by a **small-number run** (`1,2`). |
| **minimum** | The smallest number. Here it is always the **first number of the small-number run**, the spot where the list "drops". |

## How to come up with it (the thinking)
**Step 1: the obvious idea.** Look at every number and remember the smallest. O(n), but the problem wants O(log n), which hints at **binary search**.

**Step 2: can we throw half away?** Look at the middle number `m` and compare it with the left end:
- **`nums[m] >= nums[l]`** → the middle is in the **big-number run**. The drop (and the minimum) must be somewhere to the **right**, so discard the left half.
- **Otherwise** → the middle is in the **small-number run**. The minimum is at `m` or to the **left**, so discard the right half.

**Step 3: an early win.** If `nums[l] < nums[r]`, this slice isn't rotated at all (it's fully sorted). Its smallest number is simply `nums[l]`. We can stop.

**Step 4: don't forget to remember.** Each middle we look at might be the minimum, so keep `res = min(res, nums[m])` along the way.

## Solution
```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        res = nums[0]
        l, r = 0, len(nums) - 1

        while l <= r:
            if nums[l] < nums[r]:
                res = min(res, nums[l])
                break

            m = (l + r) // 2
            res = min(res, nums[m])
            if nums[m] >= nums[l]:
                l = m + 1
            else:
                r = m - 1
        return res
```

## Line by line
| Line | What it does |
|---|---|
| `res = nums[0]` | Smallest number seen so far; start with the first one. |
| `l, r = 0, len(nums) - 1` | Search the whole list at first. |
| `while l <= r:` | While there's still a part left to search. |
| `if nums[l] < nums[r]:` | This slice is already in order (no rotation inside it)... |
| `res = min(res, nums[l]); break` | ...so its first number is its smallest. Record it and stop. |
| `m = (l + r) // 2` | Middle position. |
| `res = min(res, nums[m])` | The middle might be the smallest, so record it. |
| `if nums[m] >= nums[l]: l = m + 1` | Middle is in the big run → the minimum is to the right. Discard the left half. |
| `else: r = m - 1` | Middle is in the small run → the minimum is at `m` or to the left. Discard the right half. |

## Watch it run
`nums = [3, 4, 5, 6, 1, 2]` (positions 0 to 5)

| Round | `l` | `r` | `nums[l]` < `nums[r]`? | `m` | `nums[m]` | `res` | Decision |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 3 < 2? No | 2 | 5 | 3 | 5 ≥ 3 → big run → `l = 3` |
| 2 | 3 | 5 | 6 < 2? No | 4 | 1 | 1 | 1 ≥ 6? No → small run → `r = 3` |
| 3 | 3 | 3 | 6 < 6? No | 3 | 6 | 1 | 6 ≥ 6 → `l = 4` |

Now `l > r`, so the loop ends. Answer: **1** ✅

## How fast is it?
- **Time: O(log n).** Half of the list is discarded each round.
- **Space: O(1).**
